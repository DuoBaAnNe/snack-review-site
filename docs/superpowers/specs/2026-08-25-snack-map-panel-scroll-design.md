# 零食地图省份卡片滚动定位修复设计

## 问题

用户在零食地图中点击省份后，省份零食缩略卡片会固定在浏览器视口中。页面上下滚动时，地图随文档移动，但卡片停在屏幕原位，卡片与被点击省份脱离。

根因位于 `src/components/SnackMapView.tsx`：卡片使用 `position: fixed`，状态中保存的是鼠标事件的 `clientX`、`clientY` 视口坐标。

## 目标行为

- 卡片出现在省份点击位置右侧，保留现有偏移量。
- 卡片固定在地图容器内部的点击位置，而不是固定在浏览器视口。
- 页面滚动时，卡片与地图同步移动；地图滚出视口时，卡片也滚出视口。
- 悬停卡片和点击后固定的卡片采用相同坐标规则。
- 保留关闭按钮、缩略图导航、样式和省份选择行为。

## 方案

在 ECharts 鼠标移动和点击事件中，将视口坐标转换为地图容器内部坐标：

```text
localX = clientX - containerRect.left
localY = clientY - containerRect.top
```

卡片状态保存 `x`、`y` 容器坐标。卡片改为相对已有 `relative` 地图容器的 `absolute` 定位，并继续应用当前的水平 `+18px`、垂直 `-30px` 偏移。

不增加滚动监听器。浏览器的正常文档布局会自动让绝对定位卡片跟随地图移动，避免滚动过程中的重算、抖动和额外渲染。

## 测试

先增加纯函数测试，定义并验证：

- 视口坐标会减去容器边界得到容器内部坐标。
- 生成的卡片定位方式是 `absolute`。
- 现有 `+18px`、`-30px` 偏移保持不变。

测试需先在现有实现上按预期失败，再进行最小代码修改使其通过。之后运行项目现有测试、ESLint/构建检查，并在本地页面中点击有零食的省份，分别向上、向下滚动，确认卡片始终与地图同步。

## 非目标

- 不改变卡片内容或视觉样式。
- 不改变地图缩放、着色、标签和省份数据。
- 不修改省份争霸战地图。
- 不增加新的弹层库或滚动定位依赖。
